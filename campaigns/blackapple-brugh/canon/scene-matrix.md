# Feature-to-scene and runtime matrix

This matrix is the authoring gate for `campaign.blackapple-brugh`. It was
checked against the baseline Core, CLI, Game, and `fifth-srd` sources at the
start of task #9294. “Supported” means the current contract can express the
behavior without a new owner. “Authored” means the behavior still needs
campaign definitions. “Gap” means the story contract is settled but a named
Core or product task must supply the missing persistent or presentation
capability. No row claims that a Blackapple runtime module already exists.

The scene IDs are logical canon IDs. Their initial runtime mapping is in
[README.md](README.md); definition IDs use underscores when the module is
created.

## Authoring order implied by the matrix

1. Land the approved member-perception event/check/storage/view contract from
   #9362 (and only that generic runtime seam) before authoring the paired
   glamour/truth scenes that depend on it.
2. Author the scalar child, double, ending, and epilogue variables named in
   [README.md](README.md); they use the existing campaign save contract and do
   not need a new Core collection.
3. Create and validate `blackapple-fae` only for concrete source-specific data,
   including the `fifthsave_int` shape and any creature conversions accepted by
   the source/ShareAlike boundary.
4. Author campaign areas and ordinary event chains against the supported
   `fifth-srd` services, movement, combat, and saves.
5. Author the paired Brugh descriptions and return renderer once the approved
   per-member projection exists; `blackapple-art` supplies original assets and
   shared geometry.
6. Run module validation, headless play/sim, focused tests, save/load checks,
   and golden transcripts. A module validation pass does not establish that a
   player-visible glamour/truth interaction works; that requires a runtime
   proof after #9362.
